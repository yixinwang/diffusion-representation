## Frozen workload and validation

CPU Torch generator seed 20260909 creates float32 source `N(0,1)` with shape (64,2880) and raw width/height/derivative tensors `N(0,0.2²)` with appended dimensions 8/8/7. Defaults: tail bound 3, min width/height/derivative 1e-3, identity tails. The exact same preserved tensors serve every implementation. Forward timing applies the forward function to these Gaussian coordinates; inverse timing applies the inverse function to these same coordinates in its output domain. It does not time inversion only on favorable outputs. Preserve all fabricated tensors and hashes. Additional small float32 and float64 cases are shape (4,17), seeds 20260910/20260911 with the same parameter distribution. The first small float32 array supplies all gradient checks. The scalar batch represents 2880 conditioned coordinates per 64 examples, but there is no conditioner/model workload.

Every dense invocation accepts results only after exactly one host `bool(valid)` check of its aggregated device validity scalar, outside the compiled graph. The reference retains every existing validation and synchronization. Do not disable checks, clip failures, return partial accepted outputs, ignore invalid status or silently substitute a fallback. Static shape/dtype/configuration are checked by the eager dense wrapper before each shape enters the compiled kernel; compiled calls reuse those same fixed metadata. Gradient checks also reject invalid status before backward. Every warmup and measured call is validated.

Before any warmed performance samples: compare forward and inverse values and per-coordinate logdet against reference for full float32 and both small arrays. Require absolute error≤1e-4 with zero relative tolerance in float32; the small float64 diagnostic requires≤1e-10 with no timing claim. Check each implementation's inverse(forward(x)) against x and forward+inverse logdet against zero at the same tolerances. Gradient checks differentiate sum(value+0.1*logdet) with respect to source and all three raw parameter tensors, in both directions, on the small float32 case. Every gradient coordinate must satisfy `abs(error)≤1e-4+1e-3*abs(reference)`. These are numerical implementation gates, not statements about learned representations or a whole composition's accumulated error.

Any failed comparison saves actual/reference arrays and diagnostic maximum discrepancies, then stops before warmups/timing. Exceptions/invalidity/compiler failure similarly stop, preserve inputs, sources, completed diagnostics and failure status. A failed gate may not be relaxed within this run. Fullgraph compilation failure is an observed compatibility failure; no graph-break or eager fallback is allowed. Float64 diagnostics and gradient compilation can introduce additional graphs; their first-use costs remain visible.

## Measurement and accounting

After all gates pass, run 10 warmups for each of six implementation×direction combinations, with validation. Then run 30 repetitions; each repetition includes all six combinations once in a permutation from Python `random.Random(20260910)`, persisted exactly. Use the same input tensors throughout. CPU and BLAS computation uses one thread; reserve 4 CPUs for the GPU allocation/compiler. No other jobs or users are queried or controlled.

For every checked call, synchronize first, reset CUDA peak statistics, create events, start wall time, record the start event, invoke and validate the function, record end event, synchronize, and stop wall time. Report event milliseconds and synchronized wall seconds for all 180 samples; event spans include stream-idle gaps caused by host-side validation/dispatch and are not claimed to be pure kernel execution. Wall measurement charges validation synchronization and event overhead equally. Report allocation before call, peak allocated/reserved and incremental allocated peak. Resident input tensors and compiler state are shared in this process; absolute memory is not a clean isolated deployment measurement. No allocator cache emptying between arms. Output tensors are deleted after each sample.

First-use setup wall time for each implementation, direction, shape and gradient case is recorded separately before numerical gates complete. It can include compilation, execution and validation; it is not a pure compiler measurement or a warmed performance sample. Record the total of compiled first-use times, including float64/gradient graphs, without presenting it as the production-only compilation bill. No break-even claim follows: deployment shapes, recompilation, workload call count and full-model costs remain unknown. Provide per-variant medians and all repetitions, no statistical significance or broad speedup claims from repeated fixed inputs. Report adverse latency/memory/compiler outcomes as observed.
