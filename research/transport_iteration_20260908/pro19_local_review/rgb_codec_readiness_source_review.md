# RGB codec readiness runner: bounded independent source review

Reviewed run.py, PROTOCOL.md and relevant RGBCodecFlowMatching/PixelFlowMatching stage APIs. No data were opened, no model instantiated, and no job/test was run by this reviewer.

The intended execution is internally consistent: default latent model starts in codec stage; codec loss trains only codec parameters. Setting normalization freezes both modules; freeze_normalization transitions to flow with frozen codec and enables the latent field. The normalized synthetic cache is then valid input to training_loss_from_latents. Sampling explicitly selects inference. Pixel model starts in flow and also switches to inference. Parameter totals match the previously checked counts. Full source dimensions differ honestly:1024 latent versus3072 pixel. Finite scalar loss, every selected gradient, and every post-step parameter are checked. No optimizer or canonical image loader is implicitly invoked outside the prescribed synthetic work.

Source closure includes the module, qalt package initializer/core import, runner/protocol and component tests. Expected commit must equal full HEAD and each listed source matches its Git blob before synthetic input creation. The eventual Slurm launcher is not currently present/listed; freeze and include it (or preserve its independently authenticated submission bytes) before submission. Source modules import before guard, but the guarded module has no data access and its dependencies are enumerated; do not claim this is a sandbox against untrusted import side effects. The environment record includes actual device and thread count. Protocol says V100-32 but runner only asserts CUDA, so launcher/device validation must enforce or independently review that scope rather than accepting another GPU as the specified measurement.

Measurements are deliberately small: five warmup+twenty timed batch32 updates and one batch125 update per stage; sampling one warmup+three timed calls at batches1 and32. The runner does not silently claim the proposed final20/100 batch125 sampling profile. Checkpoint timing includes serialization of CUDA state to disk plus fsync. Cache timing includes encoding/transfer/write and returning the cache to CUDA; this is explicit and conservative. AdamW construction occurs before the per-update clock; whole execution wall includes it, but per-step medians do not. Sampling includes decoder for latent, but does not remove its frozen encoder or synthetic cache. Memory is therefore resident whole-screen memory with x32/x125, inactive encoder, normalization/cache and model buffers, not optimized inference-only memory or a final complete-cost budget.

Recommended failure/measurement hardening before screen:

1. Write the completed batch32 report immediately after adding batch32_memory, before attempting batch125. Presently an OOM125 leaves the disk JSON without that already measured peak or p50/p90. Add a train_profile finally/exception record with attempted batch, iteration and safe memory counters; outer failure checkpoint/trace alone does not preserve the stage's measurement evidence.
2. Save sampling timing progress and the latest successful sample after each completed call. Presently a later failed call loses all earlier successful timings/output for that batch, because output/JSON are written only after all four calls.
3. Avoid retaining the previous GPU `values` output while timing the next call: save then delete it before the next invocation, or explicitly disclose this in peak accounting. The batch1 output also stays alive into batch32 until assignment. This is a small but avoidable memory-retention confound. Source tensors and synthetic inputs/cache intentionally resident in both cases must remain separately labelled.
4. On exceptional sampling/training, persist memory counters when safe, including the first failing large-batch attempt; preserve the original failure without a reduced-batch retry. Do not turn a failed batch125 check into readiness by reporting batch32 alone.

The outer failure path otherwise saves a synthetic model checkpoint and traceback, and the finally manifest includes partial payloads; original output directories cannot be overwritten. No NaN/Inf scalar statistic is intentionally accepted into the report because losses are rejected before conversion. Failure in checkpoint saving is separately recorded. Tests run from the expected repository and use fabricated inputs; their pass does not establish real codec quality or an FM adequate for the eventual baseline.

No stage/API/count blocker found. This is readiness-only source approval subject to the concrete preservation/accounting fixes above and source/device freeze; no real-data or final-budget qualification is implied.
