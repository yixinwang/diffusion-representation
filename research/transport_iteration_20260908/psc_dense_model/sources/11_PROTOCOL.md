## Equivalence before timing

For batch sizes one and 64, evaluate the complete original `run_shared.generate` pipeline: common source, shared coarse FM with 32 actual calls, generated coarse context, the selected residual coupling decoder, shared analysis inverse, and sigmoid. Preserve each arm's actual outputs before comparison. Every float32 pixel must differ from the reference by no more than 1e-4 in absolute value; nonfinite values or shape differences fail the whole case. There is no clipping or element masking to conceal failure.

Then use the first 32 common Gaussian rows to generate coarse contexts and residual coefficients with the original saved model. These generated arrays are the only inputs to the encode/NLL/backward case; no observed fitting examples are used. Preserve those arrays and the assembled/recovered analysis codes. Original residual-source and analysis-code roundtrips must be no worse than 1e-3, and their logdet cancellation no worse than 1e-2. The original coarse Heun inverse remains unverified, so this is not a complete Gaussian-source inversion certificate or a new full-density theorem.

For every decoder, run residual encoding, form the full per-array Gaussian NLL plus inverse logdet, and backpropagate the mean NLL divided by 2,880, matching the original conditional training objective's scale. Save encoded values, every per-array logdet/NLL, scalar loss, and every parameter gradient. Every parameter must have a finite gradient. Encoded-coordinate absolute tolerance is 1e-4; per-array logdet and unnormalized NLL tolerance is 1e-2; scalar loss tolerance is 1e-2. Every parameter gradient uses absolute difference bounded by `1e-4 + 1e-3*abs(reference_gradient)`. These are disclosed float32 implementation tolerances and supply no interval or relative-accuracy guarantee for tiny gradients.

All output and gradient equivalence gates finish before steady timing. An exception retains saved outputs, setup records, phase, traceback, and elapsed time. A source or compilation failure stops the run; no substitute benchmark or changed tolerance is attempted.

## Timing and cost accounting

There are three cases: full pipeline batch one, full pipeline batch64, and generated-input encode/NLL/backward batch32. Each arm receives ten warmups for each case. Then run thirty repetitions in independently shuffled arm order from fixed order seed2026091101. Preserve the complete order and raw synchronized wall and CUDA-event measurements. All arms use the same inputs. Only the selected decoder is resident on the GPU for a call; other decoder parameters and gradients are offloaded. Shared analysis is resident for pipeline calls and offloaded for residual-only backward calls. The common source bank and generated backward inputs are fixed benchmark buffers, reflected in the reported baseline memory.

Model movement occurs outside the timed call and is reported separately. The CUDA allocator cache is retained across interleaved repetitions; reserved-memory baselines therefore include allocator history and are not interpreted as isolated per-arm model storage. Allocated/reserved memory before each call, allocated/reserved peaks, and incremental allocated peaks are all recorded. Each first use is timed separately for pipeline batches1/64 and inverse-plus-backward batch32, including compilation and initial execution. Model/checkpoint construction, all first uses, all warmups, and compiler cache locations are reported. Compiler specialization or setup is not silently folded into a claimed amortized saving. Compiler-cache files are retained separately but excluded from the scientific payload hash list, whose exclusions are explicit.

The backward call includes decoder validation, encoding, likelihood arithmetic, gradient clearing, and backpropagation. It excludes an optimizer step, parameter-update checks, and the original production training loop. Additional finite-result and finite-gradient checks occur outside sampled call timing and have separately recorded duration. Thus backward timing is not a training-step speed measurement. No production break-even or end-to-end training advantage is promised; such an interpretation would require the measured workload, call counts, setup costs, and full training-loop overhead.
