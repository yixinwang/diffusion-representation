# Train-only archive prerequisite

This isolated, standard-library component prepares a future video input boundary. It has been exercised only on fabricated tar files. No real archive, video, frame, validation/test payload, decoder, remote host, or model was opened or run.

`archive_reader.py` exposes:

- `index_archive(path)`: scan an uncompressed tar regardless of suffix, reading only 512-byte header/footer blocks and seeking over all member bodies. Return immutable member records with original path, type, header/data offsets, size, padded end, split, class, group and clip. Directory records carry no split/class identity. Regular video classification follows the pinned repository convention, including the optional `UCF101` directory after the split.
- `save_manifest(manifest, path)`: create a new JSON file without overwriting. `manifest.sha256` is the digest of its canonical JSON payload.
- `load_manifest(path, archive, expected_manifest_sha256=...)`: verify the externally retained manifest digest, rescan only headers, and require exact equality with the cached file identity and records. The digest must come from the frozen configuration, not an untrusted manifest alongside itself.
- `TrainMemberReader(archive, manifest, member_path, train_allowlist=...)`: require a nonempty explicit allowlist containing only known regular training members. Validation/test requests are rejected even if placed into the allowlist. Reindex the same open file descriptor before exposing member bytes. Positional reads are capped to the selected member; seeks outside [0,size] are rejected. Negative reads accept only standard `-1` (read the remainder); values below -1 fail. BufferedReader compatibility is tested. Reads check file identity before and after each operation; stale files fail.
- `check_pinned_metadata(manifest)`: verify the recorded canonical archive size and split/group counts. This verifies metadata only, not the pinned whole-file SHA256.

The saved provenance file binds the existing repository parser, manifest and readiness plan used for this implementation. The archive SHA256 and upstream revision are recorded provenance only. Neither `index_archive` nor a header digest verifies unseen member payload bytes. A future payload-integrity policy must explicitly authorize and record any whole-container checksum, or rely on a separately established immutable archive identity. Filesystem device/inode/size/mtime/ctime checks detect ordinary mutation and replacement, not hostile privileged manipulation of filesystem metadata. This Python file-like boundary is not a security sandbox against a caller that independently opens the underlying path or accesses private attributes.

Strict supported format: plain regular-file tar with regular video members and optional zero-size directories. Tar header checksums are checked by `TarInfo.frombuf`. All links, sparse/special records, PAX/GNU extension records, traversal, absolute paths, normalization aliases, duplicate paths/clip identities, cross-split source groups, truncated/out-of-range records and nonzero records after the terminator are rejected. At least two zero terminator blocks are required. The earlier archive description does not prove absence of extension records: real header compatibility remains unverified. Rejecting unsupported metadata is intentional; this component must not silently add extension parsing after seeing payloads.

No decoder API or automatic allowlist construction is included. A future frozen configuration must state exact selected training member names, hash that allowlist and the header manifest, preserve group identities, record each opened member, and fix timestamp/resize/color/dequantization rules before decoding. The reader's per-open header scan and all two-pass decoding work must be charged explicitly. This prerequisite does not authorize validation/test decoding or establish video data readiness.

Run the fabricated suite with `python -m pytest -q test_archive_reader.py` from this directory. Seventeen cases passed in the local Python 3.12 environment, including instrumented proof that indexing skips every fabricated body, bounded read/seek and BufferedReader behavior, protected-member rejection, traversal, symlink/hardlink/special headers, duplicates, source-group leakage, truncation, oversized member records, manifest tampering, mutation, symlink archive rejection, and checksum failure. There is no scientific result or decoder performance claim.

## Prospective guarded header audit

`run_header_audit.py` is a stdlib-only wrapper with exactly one hard-coded archive path: the existing pinned PSC archive. It has no archive override or fixture mode. Require `--expected-module-sha256 SHA256`, or `--expected-commit FULL40 --repo REPOSITORY`, or both. The Git mode verifies HEAD and exact source bytes against the named commit's blob. The wrapper saves the verified reader bytes into its exclusively created `--output` directory and imports that snapshot before indexing. It saves the metadata manifest, canonical manifest digest, exact JSON-file hash, source identity, environment, elapsed time and atomic status. A canonical metadata failure retains the already built manifest; a parser failure retains its traceback. Unsupported formats remain rejected. No train-member reader is instantiated. Archive payload hashes are not recomputed.

A local test checks Git/SHA mismatch handling against a temporary fabricated repository; another exercises only a pre-archive source-guard failure and proves status preservation/no overwrite; a third rejects archive override and checks snapshot origin/atomic status. All three passed. The wrapper was not executed against the real archive. The future operator must freeze these sources and provide their independently obtained source digest or full Git commit before running the metadata audit.
